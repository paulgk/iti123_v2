  <name>Task 1: Implement kinetic chain timing features (FEAT-02)</name>
  <files>src/data_processing/kinetic_chain_features.py</files>
  <action>
Create kinetic chain feature extraction module:

1. **extract_kinetic_chain_timing(pose_sequence, phases):**
   Measure sequential peak velocity timing through kinetic chain.

   Segments to track (MediaPipe landmarks):
   - hip: landmark 23 (left_hip) or 24 (right_hip)
   - trunk: midpoint of shoulders (11+12)/2 and hips (23+24)/2
   - shoulder: landmark 11 or 12
   - elbow: landmark 13 or 14
   - wrist: landmark 15 or 16

   Algorithm:
   a. For each segment, extract positions from pose_sequence
   b. Calculate velocity magnitude (smoothed)
   c. Find peak velocity frame WITHIN forward_swing phase only (not full sequence)
   d. Calculate time deltas between sequential peaks

   Output features:
   ```python
   {
       'hip_to_trunk_delay': int,      # frames
       'trunk_to_shoulder_delay': int,
       'shoulder_to_elbow_delay': int,
       'elbow_to_wrist_delay': int,
       'hip_to_wrist_total': int,      # total chain time
       'chain_sequence_valid': bool,   # True if delays are positive
   }
   ```

2. **calculate_coordination_efficiency(timing_features):**
   - Check if kinetic chain sequence is valid (hip < trunk < shoulder < elbow < wrist)
   - Calculate efficiency score: 1.0 if valid sequence, penalty for out-of-order peaks
   - Return efficiency metric (0-1 scale)

3. **detect_dominant_side(pose_sequence):**
   - Determine if player is right or left handed
   - Use arm elevation comparison during forward swing
   - Return 'right' or 'left'

CRITICAL: Measure kinetic chain ONLY in forward_swing phase. Measuring across full sequence will find preparation movement peaks, not power generation sequence. This is a documented pitfall in RESEARCH.md.

Use smoothing (gaussian_filter1d, sigma=1.5) before velocity calculation to reduce MediaPipe jitter.

  <name>Task 2: Implement contact frame and intent window features (FEAT-03)</name>
  <files>src/data_processing/contact_frame_features.py</files>
  <action>
Create contact frame feature extraction module:

**IMPORTANT:** Use get_intent_window() from phase_segmentation.py to calculate intent window:
```python
from src.data_processing.phase_segmentation import get_intent_window
```

1. **extract_contact_frame_features(pose_sequence, contact_frame):**
   Extract biomechanical features at the moment of contact:

   ```python
   {
       # Forearm orientation (KEY discriminative features)
       'contact_forearm_vertical_angle': float,  # Clear > 90deg, Smash < 90deg
       'contact_forearm_pitch': float,           # Elevation above horizontal

       # Wrist-elbow relationship
       'contact_wrist_elbow_vertical': float,    # Clear: wrist above, Smash: below
       'contact_wrist_height': float,            # Absolute wrist Y position

       # Arm extension
       'contact_elbow_extension': float,         # Elbow angle at contact
       'contact_arm_extension': float,           # Shoulder-wrist distance

       # Body posture
       'contact_torso_lean': float,              # Forward lean angle
       'contact_shoulder_rotation': float,       # Shoulder turn angle
   }
   ```

2. **extract_intent_window_features(pose_sequence, contact_frame):**
   Extract features from intent window [contact-5 : contact-2] frames.
   This is the MOST discriminative window per coaching insights.

   **Use get_intent_window(contact_frame) from phase_segmentation.py** to get the frame range.

   Features (computed within intent window):
   ```python
   {
       # Elbow lead (PRIMARY - 35% weight in SIS)
       'intent_elbow_forward_mean': float,      # x(elbow) - x(shoulder)
       'intent_elbow_forward_max': float,

       # Forearm pronation velocity (PRIMARY - 30% weight in SIS)
       'intent_forearm_rotation_vel': float,    # Angular velocity of forearm

       # Non-racket arm pull (SECONDARY - 15% weight in SIS)
       'intent_nonracket_arm_drop': float,      # dy of non-dominant wrist

       # Trunk rotation (TERTIARY - 10% weight in SIS)
       'intent_torso_rotation_vel': float,      # Rate of torso twist

       # COM direction (TERTIARY - 10% weight in SIS)
       'intent_com_velocity_y': float,          # Vertical COM velocity
   }
   ```

3. **calculate_smash_intent_score(intent_features):**
   Implement coach-validated SIS formula:
   ```
   SIS = 0.35*E + 0.30*P + 0.15*N + 0.10*T + 0.10*C
   ```
   Where each component is normalized 0-1 based on research reference values.

   Return:
   ```python
   {
       'smash_intent_score': float,  # 0-1 scale
       'classification_hint': str,   # 'smash', 'clear', 'deceptive'
       'component_scores': dict      # Individual E, P, N, T, C scores
   }
   ```

   Thresholds from research:
   - SIS >= 0.65: Smash
   - 0.40 <= SIS < 0.65: Deceptive/Half-smash
   - SIS < 0.40: Clear

Handle edge cases:
- contact_frame < 5: Use available frames [0 : contact-2]
- Missing landmarks: Return NaN for affected features, not failure
  </action>
